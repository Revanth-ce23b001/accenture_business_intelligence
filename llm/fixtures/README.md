# Fixtures

Recorded model responses, replayed by `MockProvider` when `MOCK_LLM=true`.
CLAUDE.md rule 8: the full demo runs offline from these, and that has to
work from day one.

Each file is `<request-fingerprint>.json`. The fingerprint is a SHA-256
over the canonical form of the `LLMRequest`, so a fixture is found by the
exact call that would otherwise have been made — change the prompt, the
model, the candidate tags or the batch and it is correctly a miss.

## Two kinds of fixture, and the difference matters

A fixture carrying `"synthetic": true` is **not a recording**. It was
generated by `llm/record_fixtures.py --offline` from a keyword stand-in,
because a repository has to be buildable and testable without an API key.

Be clear-eyed about what a synthetic fixture proves:

- it **does** prove the pipeline — batching, the content-hash cache, the
  parsing, the counting, the chi-square, and the rule that no number
  reaches a case from a model response;
- it **does not** prove the model's judgement. It says what the stand-in
  decided about a note, not what Haiku would decide.

Re-record against the live API before quoting any classification accuracy:

```bash
export ANTHROPIC_API_KEY=...
python -m llm.record_fixtures --live
```

That rewrites the same fingerprints with real responses and drops the
`synthetic` flag. Everything downstream is unchanged — the engine cannot
tell the difference, which is the point of the boundary.

## Regenerating offline

```bash
python -m llm.record_fixtures --offline
```

Needs `data/casefile.duckdb`, because the batches are built from the real
documents the case would classify.
